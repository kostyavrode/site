# Единый код для теста и продакшена

## Как это работает

**НЕ НУЖНО покупать отдельный домен!** Один и тот же код работает и на тесте, и на проде.

### Автоматическое определение окружения

Код автоматически определяет окружение на основе URL:

1. **Тестовая среда на продакшене**: путь начинается с `/test/`
   - URL: `https://audio-kostya.online/test/groups.html`
   - API endpoints: `https://audio-kostya.online/test/api/...`

2. **Продакшен**: обычный путь без `/test/`
   - URL: `https://audio-kostya.online/groups.html`
   - API endpoints: `https://audio-kostya.online/api/...`

3. **Локальная тестовая среда**: порт 8001 или параметр `?test=true`
   - URL: `http://localhost:8001/groups.html`
   - API endpoints: `http://localhost:10001`, `http://localhost:10002`, и т.д.

4. **Локальная разработка**: порт 3001 или другой
   - URL: `http://localhost:3001/groups.html`
   - API endpoints: `http://localhost:5001`, `http://localhost:5002`, и т.д.

### Единая логика инициализации

Вся логика определения окружения находится в одном месте: `site/js/api.js` в методе `API.initBaseUrls()`.

Этот метод автоматически вызывается при первом API запросе, но можно вызвать вручную:
```javascript
API.initBaseUrls();
```

### Преимущества

✅ **Один код** - не нужно поддерживать две версии  
✅ **Автоматическое определение** - не нужно вручную настраивать окружение  
✅ **Без отдельного домена** - используем префикс `/test/`  
✅ **Легко тестировать** - просто откройте `/test/` версию сайта  

### Развертывание

1. **Продакшен**: разверните код из ветки `main` в `/opt/audio-kostya/site/`
2. **Тест**: разверните тот же код из ветки `main` в `/opt/test/audio-project/site/`

Или используйте один и тот же код для обоих - Nginx будет обслуживать разные пути из одной директории.

### Nginx конфигурация

Nginx настроен так, что:
- `/` → продакшен (проксирует на порты 5001-5005)
- `/test/` → тест (проксирует на порты 10001-10005)

Оба пути могут обслуживаться из одной директории с файлами сайта.
